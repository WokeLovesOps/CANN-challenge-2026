# 点2：当前正式版的A3瓶颈分析

## 结论

当前点2已经是固定UB、显式同步、索引生成与输入搬运重叠的纯Vector核。上一版“优先去队列、前移索引”的优化已经落地，不能再当作当前建议。

剩余开销主要包括入口控制与输入固定延迟、8次Gather的串行重排、点积和Max-Sum归约、输出固定延迟。Cast很短，计算规模也小，不支持优先换Cube、多核或C/V融合。另有明显预热敏感性，需要与核内优化区分。

本次未修改正式算子，使用当前完整库，重新采集真机和Ascend910_9362软件模型。没有使用旧Ascend910B3模型的时序来解释本次结果。

## 实际路径与工作量

仓库自主构造的代表输入B/M/N/K=1/3/5/40，BF16、TN；不是对官方隐藏形状的确认。

Profiler实际核名为_ZN13batch_max_sum23ComputePackedCastGatherIu6__bf16Lb1ELb0EEEvPhS1_S1_jjj，类型vector，Block Dim=1，对应ComputePackedCastGather<bfloat16_t,true,false>。

当前通用分派条件是batch=1、K≤64、M×N≤16及BF16/TN，另有上游题面有效性检查。运行时M/N/K传入核函数，不是针对3/5/40特判。

- 输入A=120个BF16，B=200个BF16，共640字节；输出一个FP32，4字节。
- 输入在UB按32字节对齐放置，A占用128元素槽，B紧随；Cast共转换328个元素，含8个不会参与Gather的对齐间隙。
- 3次A Gather及5次B Gather，得到连续K数据，当前每条向量占64元素槽。
- 3条重复Mul完成15个长度40的点积乘法，共600次乘法。
- 一条重复WholeReduceSum求15个点积，一条重复WholeReduceMax求3行最大值，最后一次WholeReduceSum输出。
- 不需要Cube，不经过Cube到Vector的中间GM写回，不存在点7那种C/V等待。

## 匹配A3模型的时序

core0第二次采集调用，指令跨度约0.850μs，时间相对自身首条记录。模型值用于定位依赖，不能当作真机延迟。

| 阶段 | 起止μs | 说明 |
|---|---:|---|
| 入口到首次输入搬运 | 0—0.211 | 参数、地址、掩码及事件等控制，不是TPipe开销 |
| 输入A | 0.211—0.362 | 240字节有效输入 |
| 输入B | 0.212—0.366 | 400字节有效输入，与A重叠 |
| 索引Vector生成 | 0.253—0.356 | 4条VADDS、2条VMULS，已被输入搬运覆盖 |
| 合并Cast | 0.366—0.380 | 一条VCONV，约0.014μs |
| 8次Gather | 0.382—0.537 | 约0.155μs，当前重排链 |
| 3条重复Mul | 0.539—0.589 | 约0.050μs |
| 15个点积Sum | 0.590—0.666 | 一条VCADD，约0.076μs |
| 3个行Max | 0.676—0.700 | 一条VCMAX，约0.024μs |
| 最终Sum | 0.701—0.724 | 一条VCADD，约0.023μs |
| 输出搬运 | 0.725—0.850 | 4字节有效输出，仍有固定延迟 |

从当前依赖看，继续缩短索引生成不一定缩短临界路径，因为它在输入就绪前已完成。索引生成改得更复杂反而可能超过0.366μs而重新阻塞Cast。

Gather约占这个模型总跨度18%，属于可研究的一段，但并非唯一瓶颈；即使减少其指令，也必须把新增索引、同步和布局处理算入总成本。不能把这18%解释成真机可获得的加速比例。

## 下一步优先级

1. **优先研究批量Gather与紧凑K布局的独立候选。** 当前每行/列独立Gather，合计8次。可先限定一般条件K按8对齐，使FP32连续K行仍32字节对齐，将A和B各自的重排尽量合并成批量Gather；Mul及点积归约使用K/8的repeat行跨度，其他K保留当前实现。完整索引必须依据运行时M/N/K生成，不能预存某个测试形状的索引表。具体API及计数范围仍需实施时验证。
2. **该候选有明确风险。** 批量Gather需要构造更多索引，可能抵消减少发射次数的收益；不能只比较Gather条数。第一验收是匹配模型的Cast开始时间不能因索引变晚，且Gather到最终输出的整体链确实缩短，再用同预热口径ABBA真机对照。
3. **暂不优先重复去队列、改Cast、改Max掩码或纯粹增加核数。** 当前已经无TPipe队列；Cast约0.014μs，Max掩码小改此前无稳定收益；15个短点积用多核会增加分发和归约开销。换Cube或C/V融合会增加输入布局和结果交接，不具备本轮证据支持。
4. 不可将max(sum_K)改成sum_K(max)，也不可用FP16中间计算替代当前FP32而不验证精度。所有优化继续保留题面合法域回退和300秒远端完整编译限制。
