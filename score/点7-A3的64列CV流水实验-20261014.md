## 实现

完整候选：Build/Point7CV64A320261014/src/kernel.asc。

在原FP16/TN、M≤32、N≤128、K≤256且K按16对齐、batch不超过可用核数的驻留路径中，N>64时启用ComputeBatchResidentTNCV64。其余分派保留。这里按布局、尺寸区间和容量选择，不按测试编号或精确形状白名单选择。

A/B仍完整搬入L1一次；A完整K驻留L0A复用。L0B采用两个64×K的half槽，K=256时合计64KiB；L0C采用两个32×64的float槽，合计16KiB。两个GM结果槽不复用，第一块占32×64个float，第二块使用实际尾列向上对齐到16的行跨度，总需求不超过原scratch分配。

两块各做完整K的FP32累加、Fixpipe，分别通过模式2、PIPE_FIX的flag8/9通知Vector。Vector逐块求行Max，再逐行合并Max，最后只做一次Sum。没有FP16中间结果，没有输出硬编码，保留原合法输入回退。

## A3模型解释

core0第二次采集调用，各侧以自身首条指令为零点，单位μs。两侧首条记录相差约0.001μs；即使考虑这一偏移，也不存在首块Vector读回与第二块MMAD的时间重叠。

| 阶段 | 候选起止时间 |
|---|---:|
| 第一块MMAD | 1.301—1.382 |
| 第二块MMAD | 1.440—1.521 |
| 第一块Fixpipe | 1.386—1.555 |
| 第二块Fixpipe | 1.559—1.835 |
| Vector第一块读回 | 1.575—1.795 |
| Vector第一块行Max | 1.806—1.940 |
| Vector第二块读回 | 1.941—2.155 |
| Vector第二块行Max | 2.157—2.291 |

首块读回与第二块Fixpipe发生重叠，第一块行Max也有少量与第二块Fixpipe重叠；但第二块MMAD在Vector首块读回之前已经结束。由此没有实现原本希望的明显Vector与后续MMAD计算重叠。

分块后LOAD_2D由18条增至34条，MMAD与Fixpipe由各1条变为各2条，行Max由1条变为2条。B的总有效搬运量没有减少，更多指令和两次小块搬运增加开销。Vector使用一个输入槽，第二块读回还需等待第一块归约释放槽位。

匹配A3基线与候选的模型跨度分别为：Cube 1.661→1.843μs，Vector 2.295→2.459μs。模型结果用于解释本候选，不能替代真机计时；但它与真机未加速的观察一致。
