## 实现方法

- 保留全部Vector系列与SplitK，以及已测热点使用的6组Compute配置：32×128非分N静态基块、128×256分N／非分N静态基块、256×128分N静态基块、512×64非分N动态基块、64×256分N动态基块。每组仍保留两类型、四布局。
- 冷路径改为32×128的ComputeGeneric，N分片、直接输出、分片数、partial步长通过独立GenericParameters下发。重新计算rowTiles、核数、Matmul tiling及工作区，禁止复用被删除专用块的旧参数。
- 原Parameters布局和7个原核函数体保持不变。没有按输入数据内容选择结果，也没有跳过真实矩阵计算。
- 可重定位设备ELF统计确认225个入口组合降为105个：97个保留入口＋8个通用入口。共同153个AIC/AIV代码段逐字节相同；原始src入口的原版／候选对照也得到153/153相同；均限于各自同参数构建的未完成重定位代码段，不跨入口比较，不替代上板性能证明。
- 本地带调试信息共享库从442,033,112字节降到185,537,088字节。`-j4`仍只有一个主要ASC翻译单元，Cube与Vector代码生成主要串行执行，裁剪重复实例化比增加make并行度更直接。

## 复现编译

先在本地加载SDK，再从各自提交导出独立源码；目录必须是本次新建的空目录。下面以候选为例，原版将提交替换为 `3acbe89` 并换用另一目录。构建同一主机的两个版本时串行执行。

```bash
source /mnt/newdisk/Ascend/cann-9.0.0/set_env.sh
mkdir -p /mnt/newdisk/cann-prune-recheck/candidate-source
git archive 1e4fcee src | tar -x -C /mnt/newdisk/cann-prune-recheck/candidate-source
cmake -S /mnt/newdisk/cann-prune-recheck/candidate-source/src \
  -B /mnt/newdisk/cann-prune-recheck/candidate-build -DNPU_ARCH=dav-2201
/usr/bin/time -v cmake --build /mnt/newdisk/cann-prune-recheck/candidate-build -j4
```
